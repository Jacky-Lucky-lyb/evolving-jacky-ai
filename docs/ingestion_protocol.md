# Evolving Self AI · 内容接入 SOP v0.1

## 处理状态机

1. `INBOX`: 保留原文件及接收时间，不修改原始内容。
2. `EXTRACTED`: 模型提取候选节点、候选关系；每条附原文定位，不写入正式图谱。
3. `MATCHED`: 通过 ID / 别名 / 相似文本匹配已有节点；无法确信时新建候选，不自动合并。
4. `VALIDATED`: 校验结构、端点类型、证据定位、隐私级别、重复与冲突；不合格退回。
5. `PENDING_REVIEW`: 提交新增、更新、合并、关系给用户批量审阅。
6. `APPROVED`: 明确批准后，执行一次原子提交，生成变更日志与快照。
7. `INDEXED`: 重建 nodes.json、搜索索引和图缓存，供 Current/Potential Self 检索。

## 审核策略

- 关于「我掌握什么」「我认同什么」「我如何决策」的新增结论，必须本人确认。
- 技术知识关系也需要可定位来源；来源无法定位的关系只能待审核，不能假称已验证。
- `KNOWS` 和 `HAS_SKILL` 的起点必须是 PERSON，终点分别是 CONCEPT 和 SKILL，需本人表现或实践证据；仅上传资料不构成掌握。
- `hypothesized` 节点不允许进入 `current` 空间；`external` 资料不是本人观点。
- `rejected` 关系保留在审核日志中，不加载到正式检索图。
- 未授权 Agent 一律只读；删除、公开、外发均需单独明确批准。

## 关系判定

- 只从 `relation_schema.yaml` 中选择关系；不能使用 `RELATED_TO` 作为万能关系。
- 事实关系和观点关系区分：`SUPPORTS` 表示支持证据而非因果证明。
- 关系方向固定：`REVISED_BY` = 旧观点 → 新观点；`PART_OF` = 子项 → 母项。
- 重复关系指相同 `from + relation + to`；多个证据放入同一关系的 `evidence` 数组。
- 不能由文件的相邻位置、语义相近或共同出现自动推断 `REQUIRES`、`SUPPORTS`。

## 修改和回滚

- 正式节点 ID 一经分配不得复用；文件改名不得改 ID。
- 修改观点、来源、学习掌握等级要留日期与理由；更替观点建议建新节点，使用 `REVISED_BY` 连接。
- 批次提交前备份数据；记录批次号、操作、操作者、时间、变更对象及前后版本。
- 失败必须整体回滚；从 `audit_log.jsonl` + 快照恢复。

## 隐私与导出

- 默认 `private`。`sensitive` 禁止发给云端模型，除非用户单独批准具体内容。
- 原始资料与结构化索引分离；公开代码仓库严禁上传私人真实数据。
- 导出至少支持 Markdown + JSON；导出关系保留 ID 与证据锚点。
